>
> - 【必考】几乎每轮技术面都会问，答不上直接减分，必须能脱稿讲清

## 场景题

1. 【必考】如果让你设计一个短链接系统，你会怎么设计？（发号器（号段 / 雪花）+ 62 进制编码，6 位约 568 亿；避免哈希截断冲突；可对 ID 混淆防遍历；MySQL 存映射 + Redis / 本地缓存扛读，布隆过滤器防穿透；用 302 而非 301，保证能统计点击；统计走 MQ 异步；过期策略、恶意链接检测、生成接口限流）
2. 【必考】订单下单后 30 分钟未支付要自动取消，你会怎么实现？各种方案怎么选？（定时扫表：简单但有延迟、压库，需索引 + 分批；MQ 延迟消息（RocketMQ 定时消息 / RabbitMQ TTL + 死信）：推荐主方案；Redis ZSet 轮询、时间轮：注意并发与持久化问题；主方案 + 定时扫表兜底；取消幂等 + 状态条件更新防与支付并发；回补库存、券也要幂等）
3. 【必考】如何保证接口幂等，防止用户重复提交或者网络重试导致重复下单？（来源：用户连点、超时重试、网关重试、MQ 重复投递；前端置灰只是体验优化；Token 机制：Redis 原子删除成功才处理；业务唯一键 + 唯一索引；状态机条件更新（影响行数判重）；分布式锁只防并发；重复请求返回首次结果；封装注解 + AOP 组件）
4. 【必考】支付系统怎么防止重复支付？和第三方支付的对账怎么做？（一单一笔进行中支付单 + 状态条件控制 / 分布式锁；唯一商户订单号让第三方幂等；回调验签 + 状态条件更新幂等；下游通过 MQ 且各自幂等；定时主动查询兜底；识别跨渠道重复支付自动退款；每日对账：长款、短款、金额状态不一致 → 差错单，自动处理或转人工）
5. 【必考】热点商品库存扣减，数据库单行更新成为瓶颈怎么办？（瓶颈：单行行锁串行，连接池被占满；扣减前移 Redis（Lua）+ 异步批量合并写库；库存拆分多行 / 多 key 提升并发，配合再平衡；条件更新 where num >= 1；热点行排队优化；请求合并、排队限流；定期对账与超时回补）
6. 【必考】下单涉及订单、库存、优惠券、积分多个服务，怎么保证数据一致？（区分强一致（订单、库存、券）与最终一致（积分、通知）；低并发：Seata AT 全局事务，侵入小；高并发：TCC / 预扣 + 确认 + 超时释放，与订单超时取消流程结合；可靠消息 + Saga：本地消息表或事务消息驱动，失败发补偿；原则：全链路幂等、每步有补偿、定期对账巡检）
7. 【必考】线上某个接口突然变慢了，你的排查思路是怎样的？（确定影响面：单接口 / 全部、单实例 / 全部、开始时间点与变更关联；看大盘：QPS、P99、CPU、GC、线程池、连接池；看链路：慢请求耗时落在哪一段（DB、Redis、下游、内部）；DB：慢日志、执行计划变化、锁等待；内部：Arthas trace、jstack；先止血（回滚 / 扩容 / 降级 / 限流）再根治，复盘补告警）
8. 【必考】Redis 出现大 Key 和热 Key 问题，怎么发现和处理？（大 Key 危害：阻塞单线程、带宽、删除阻塞、集群倾斜；发现：--bigkeys、MEMORY USAGE、离线分析 RDB；处理大 Key：拆分、精简压缩、UNLINK 或分批删除、限制集合增长；热 Key：集中访问打满单分片；发现：--hotkeys（需 LFU）、客户端统计、hotkey 框架；处理热 Key：本地缓存（最有效）、多副本 key 分散、读写分离、限流）
9. 【高频】设计一个类似微博或朋友圈的 Feed 流系统，推模式和拉模式怎么选？（拉模式（读扩散）：写便宜，读时合并关注人的发件箱，读延迟高；推模式（写扩散）：读快，大 V 写放大严重；推拉结合：普通用户推、大 V 拉；只推活跃粉丝；收件箱 / 发件箱用 Redis 存 ID 并限长，内容单独存储批量取；推送走 MQ 异步；分页用游标而非 offset）
10. 【高频】扫码登录是怎么实现的？（前提：手机 App 已登录；生成二维码 ID 存 Redis（待扫描，短 TTL），PC 轮询 / 长轮询 / WebSocket；手机扫码带 Token → 已扫描待确认，返回一次性临时凭证；手机确认 → 已确认，为 PC 签发新的独立 Token；安全：ID 随机一次性短时有效、确认页展示设备地点防钓鱼、状态流转校验）
11. 【高频】设计一个高并发的优惠券领取系统，怎么防止超发和一人多领？（库存预热 Redis；Lua 原子完成判重 + 判库存 + 扣减 + 记录；MQ 异步落库削峰；数据库兜底：用户 + 券模板唯一索引；where stock > 0 条件更新；Redis 与 DB 不一致：事务消息 / 本地日志补偿 + 定时对账；热点库存拆分子 key；入口限流防刷；核销状态条件更新防重复使用）
12. 【高频】设计一个即时通讯（IM）系统，消息的可靠投递、顺序和已读未读怎么保证？（接入层 Netty 长连接网关 + Redis 路由表；逻辑层负责存储与路由；可靠投递：客户端消息 ID，发送端与接收端双 ACK + 重试 + 去重；离线消息存储，上线主动拉取：推 + 拉结合；顺序：每会话单调递增序列号，客户端按序展示，发现空洞主动拉取；已读：记录已读到的最大序列号；大群读扩散）
13. 【高频】设计一个高并发的点赞系统，点赞数怎么计数？怎么防止重复点赞？（关系（谁赞了什么）与计数分开存储；Redis Set 记录关系，Lua 原子：SADD 成功才 INCR，SREM 成功才 DECR；MQ 异步落库，唯一索引兜底；计数定时批量回刷，避免热点行；超热内容：本地聚合后 INCRBY 或拆分子 key；批量判断已赞用 Pipeline / SMISMEMBER；冷数据从 Redis 淘汰）
