30. JDK 8 升级到 17 或 21，通常会踩哪些坑？（内部 API 强封装，反射需 --add-opens 或改用公开 API；Lombok、ASM、CGLIB 等字节码框架要升级；JAXB、JAX-WS、CORBA 已移除，需自行引入依赖；CMS 移除、G1 默认，GC 参数和容量要重新验证；字符集、Security Manager 等默认行为变化要排查）

## 网络与 Netty

1. TCP 三次握手和四次挥手的过程是怎样的？为什么不能两次握手？（三次握手同步序号并确认双方收发能力；两次握手无法确认客户端收到 SYN，可能建立无效连接；全双工导致挥手要四次，FIN 只表示单向关闭；TIME_WAIT 等 2MSL，保证 ACK 到达和旧报文失效）
2. TCP 和 UDP 有什么区别？各自适合什么场景？（TCP 面向连接、可靠有序，有流控和拥塞控制；UDP 无连接、不保证到达，头部小、延迟低；不能丢数据的场景用 TCP；实时音视频、游戏、DNS 用 UDP 或上层自建可靠性）
3. HTTP/1.1、HTTP/2 和 HTTP/3 有什么区别？（HTTP/1.1 文本协议，单连接串行处理请求；HTTP/2 二进制分帧、多路复用、HPACK 头部压缩；HTTP/2 解决应用层队头阻塞，TCP 层仍有阻塞；HTTP/3 基于 QUIC，解决传输层阻塞并支持连接迁移）
4. HTTPS 的握手过程是怎样的？为什么能防窃听和篡改？（先协商套件、验证证书链，确认服务端身份；非对称算法协商密钥，对称加密传输数据；防窃听靠加密，防篡改靠 MAC/AEAD，防冒充靠证书；TLS 1.3 只保留前向安全套件，握手更快）
5. Netty 的线程模型是怎样的？为什么同一个 Channel 不用加锁？（BossGroup 负责 accept，WorkerGroup 负责读写；一个 Channel 绑定一个 EventLoop，事件串行执行；同一连接无需加锁，但要避免 handler 阻塞；耗时的业务逻辑要切换到独立业务线程池）
6. Netty 的零拷贝体现在哪些地方？（系统层用 sendfile 减少内核态与用户态复制；CompositeByteBuf 逻辑组合多个 buffer，不实际合并；slice、duplicate、wrap 共享底层内存；堆外内存减少一次堆内到堆外的复制）
7. TCP 粘包和拆包是怎么产生的？Netty 怎么解决？（TCP 是字节流，本身没有消息边界；粘包是多次写被合并，拆包是一条消息被分段；解决方案：固定长度、分隔符、长度字段、自定义协议；Netty 用 ByteToMessageDecoder 按协议边界解码）
8. Netty 的 ByteBuf 为什么要池化和引用计数？（池化复用内存，降低分配开销和 GC 压力；堆外内存适合 IO，减少一次复制；retain/release 控制生命周期，计数归零才真正释放；未释放会泄漏，可用 leak detector 定位）

6. K8s 上一次滚动发布出问题，你怎么排查和回滚？（先看 rollout status、describe 和事件；再看 Pod 日志、退出码、探针和调度原因；确认新版本问题用 rollout undo 回滚；回滚后靠 readiness 和监控确认恢复）
7. CI/CD 流水线应该包含哪些环节？怎么保证每次发布可回滚？（提交触发：构建、单测、静态扫描、质量门禁；构建不可变镜像并推送，带版本和 commit 信息；测试环境跑集成测试，生产走灰度或滚动发布；制品、配置、发布记录可追溯，支持自动回滚）

## Web 安全

1. SQL 注入是怎么产生的？预编译为什么能防住？（注入源于用户输入被当作 SQL 语法拼接；预编译把模板和参数分离，参数只当数据；配合参数校验、最小权限、错误信息脱敏；MyBatis 的 ${} 仍是拼接，优先用 #{}）
2. XSS 和 CSRF 有什么区别？分别怎么防？（XSS 是注入脚本在他人浏览器执行；CSRF 是利用已登录身份自动发请求；XSS 防输出编码、CSP、HttpOnly；CSRF 防 SameSite、Token、Referer/Origin 校验）
3. 越权漏洞怎么防？接口鉴权应该怎么设计？（水平越权是同级用户互访数据，垂直越权是低权限访问高权限接口；前端隐藏按钮不等于鉴权；服务端要做资源级校验，查询强制带用户或租户条件；统一认证、RBAC/ABAC、敏感操作二次校验和审计）
4. JWT 有什么安全问题？OAuth2 和 SSO 的流程是怎样的？（JWT 只签名不加密，payload 不能放敏感信息；固定签名算法，防 none 和密钥混淆；无状态难注销，用短过期、refresh token、黑名单；OAuth2 授权码模式用 code 换 token，SSO 共享认证中心）

## Elasticsearch

1. 什么是倒排索引？为什么 ES 能做到近实时搜索？（倒排索引是 term 到文档列表的映射；写入先进 buffer 和 translog；refresh 生成新 segment 并打开，默认 1 秒；flush 落盘，删除靠 segment 合并清理）
2. ES 的分片、副本和路由是怎么工作的？（主分片数建索引时固定，不能随意改；文档按 id 哈希取模路由到分片；副本提供高可用和读吞吐，写先主后副本；分片数量要按数据量和单分片大小规划）
3. ES 的深度分页有什么问题？search_after 怎么用？（from+size 每个分片都要取全量再排序，越翻越慢；默认 max_result_window 限制一万条；scroll 适合导出，不适合跳页；search_after 用游标向后翻，排序字段要唯一）
4. ES 的写入流程是怎样的？写入性能怎么优化？（协调节点路由到主分片，写 buffer 和 translog；refresh 让数据可搜索，flush 落盘；批量导入用 bulk、调大 refresh_interval、临时减少副本；mapping 精确、避免大文档、合理分片和 SSD）
5. MySQL 和 ES 的数据怎么同步？一致性怎么保证？（双写简单但失败难补偿，MQ 解耦但依赖消息可靠；生产多用 canal/Flink 订阅 binlog 同步；最终一致：顺序消费、重试死信、定时对账；用版本号或更新时间防乱序，查询侧容忍延迟）

## RAG

1. 什么是 RAG？为什么需要 RAG？（检索增强生成；解决 LLM 知识盲区、幻觉、私有数据无法访问、知识时效性差）
2. RAG 的完整流程是什么？（离线：文档解析 → 分块（Chunking） → 向量化（Embedding） → 入库；在线：Query 改写 → 向量检索 → 重排序 → 组装 Prompt → LLM 生成）
3. 为什么 RAG 要用向量数据库？其他数据库不行吗？（关系型数据库擅长精确匹配；向量库支持高维向量相似度检索（余弦相似度），实现语义级模糊匹配）
4. Embedding 是什么？1536 维是什么意思？（将非结构化数据映射为高维稠密向量；1536 维表示特征空间维度（如 text-embedding-ada-002），维度越高表达的信息越丰富）
5. 你是怎么分块的？块大小怎么选？固定大小分块有什么问题？（固定大小/滑动窗口/按标点切分；结合上下文窗口、语义完整性与检索精度取舍；固定大小易切断句子与段落）
6. RAG、微调、提示工程有什么区别？什么时候用哪个？（Prompt 用于快速验证与格式约束；RAG 用于注入动态私有知识、解决事实问题；微调用于改变风格/格式或注入领域深层逻辑）
7. 混合检索是什么？为什么要用混合检索而不是纯向量检索？（向量语义检索 + 关键字检索（BM25/倒排索引）；解决专有名词、SKU、人名等精确匹配召回不准）
8. 什么是重排序（Rerank）？为什么检索后还要重排序？（粗排召回 Top-K 后用交叉编码器（Cross-Encoder）精细打分；解决向量召回精度不足与假阳性结果）
9. 递归分块和语义分块有什么区别？（递归分块按分隔符层层切分；语义分块计算相邻句子向量相似度，在语义突变处切分）
10. RAG 系统常见的失败模式有哪些？检索质量差怎么排查优化？（未召回、排序靠后、上下文冗余/冲突；Query 改写、调整 Chunk、加入 Rerank、更换 Embedding 模型）
11. 什么是查询改写（Query Rewriting）？它如何提升检索效果？（将模糊/口语化提问重构为专业检索描述；多路查询扩展（Multi-Query）、上下文补全，提升召回率）
12. RAG 中的幻觉问题怎么处理？（保证检索质量与上下文准确、Prompt 强约束“依据文档回答”、输出引用来源（Citation）、必要时让模型拒答）
13. 常用向量数据库怎么选型？（开源 vs 商业、性能与扩展性、社区活跃度、混合检索支持；Milvus、Pinecone、Qdrant、Chroma）
14. 什么是假设性文档嵌入（HyDE）？它的工作原理是什么？（让 LLM 先生成假设答案，再向量化检索真实文档；解决短 Query 与长文档特征空间不匹配）

17. RAG 的文档解析与数据清洗怎么做？（PDF/Word/HTML、表格、扫描件 OCR、版面还原、去噪去重、元数据与权限标签、增量更新）

## Agent 开发

21. 什么是 Agent？与大模型有什么本质不同？核心架构由哪些组件构成？（LLM（大脑）+ Memory（记忆）+ Planning（规划）+ Tools（工具）；Profile（角色设定）、Memory、Planning、Action（工具调用））
22. Workflow、Agent、Tools 的概念和区别是什么？（Tools 是具体 API/函数；Workflow 是人类预设的固定执行路径；Agent 由 LLM 动态决策控制流，自主选择工具与执行顺序）
23. ReAct、Plan-and-Execute、Reflection 三种范式有什么区别？项目怎么选型？（ReAct 边想边做，适合动态交互；Plan-and-Execute 先规划再执行，适合步骤明确的长任务；Reflection 自我批判循环重试，适合高质量要求；按复杂度与延迟选型）
24. Agent 的记忆机制是什么？长短期记忆怎么设计、怎么存、粒度多少、怎么用？（上下文窗口 vs 向量库；滑动窗口与摘要压缩；向量库/文档库/关系型数据库；会话级/事件级/实体级；Prompt 组装时动态注入）
25. Agent 的推理模式有哪些？ReAct 具体怎么实现？（CoT 思维链、ToT 思维树、ReAct；ReAct 用 Prompt 模板强制输出 Thought → Action → Observation 循环）
26. Agent 记忆压缩通常有哪些方法？（LLM 摘要总结、滑动窗口淘汰旧信息、基于相似度检索过滤、转为知识图谱/结构化数据）
27. 什么是 Multi-Agent？多 Agent 如何分工协作与动态切换？（角色分工（产品/开发/测试）；通信协议（消息总线）、共享黑板；Router Agent 分配任务，Manager/Worker 或去中心化协作）
28. Agent 的反思机制是什么？为什么要用？怎么实现？（生成后通过 Self-Critique 发现问题并改进；解决单次生成不可靠；执行后增加验证步骤，将错误信息反馈给模型重试）
29. 复杂任务如何做任务拆分？为什么要拆分？效果如何提升？（用 LLM Planning 递归拆解子目标；突破单次上下文限制、降低单体复杂度、提高准确率与容错）
30. Function Calling 与 Tool Calling 的实现原理是什么？（工具描述 JSON Schema、模型输出结构化 tool_calls、客户端执行、结果回填、参数校验、并行调用与错误重试）
31. MCP（Model Context Protocol）是什么？解决什么问题？（标准化 Client/Server 协议、Tools/Resources/Prompts、跨模型与框架复用、权限与本地工具接入）
32. Agent 如何控制成本、延迟和死循环？（最大步数/超时/Token 预算、结果缓存、小模型路由、并行工具调用、人工兜底、失败熔断）
33. Agent 如何评测与可观测？（任务成功率、轨迹与工具调用准确率、人工评估、离线数据集、Trace（LangSmith/LangFuse）、成本与延迟监控）
34. LangChain、LangGraph、LlamaIndex、AutoGen 如何选型？（链式编排、图状态机与人工介入、RAG 索引能力、多 Agent 协作、抽象程度与可控性）
35. Agent 有哪些安全风险？如何防护？（Prompt 注入（含间接注入）、越权工具调用、数据泄露、沙箱与最小权限、高危操作人工审批、输出审核）
36. 什么是上下文工程（Context Engineering）？和 Prompt 工程有什么区别？（动态组装检索结果、记忆、工具输出，做压缩/排序/裁剪与 Token 预算，关注“喂什么”而非“怎么说”）
37. LoRA 和 QLoRA 的原理是什么？秩和参数怎么选？（冻结原权重，旁路低秩矩阵 A、B，缩放为 alpha/r；只训练少量参数，显存低、可多 adapter 切换；QLoRA 将底座 4bit NF4 量化，配合双重量化和分页优化器；r 常用 8-16，alpha 约为 2r，target 覆盖注意力与 FFN 线性层；数据和评测优先于调秩）
38. 大模型推理有哪些优化手段？TTFT 和吞吐怎么权衡？（量化压缩权重和显存，精度损失要评测；FlashAttention、算子融合、CUDA Graph 降低访存和调度开销；PagedAttention 分页管理 KV cache，提升并发吞吐；连续批处理让新请求即时补位，投机采样加速解码；单卡放不下用张量并行，多机用流水并行；权衡 TTFT 与吞吐）
39. 大模型私有化部署，开源模型和调 API 怎么权衡？（数据不能出域的业务优先私有化部署；开源模型可微调、数据可控，但要 GPU 和运维投入；API 上手快、能力强、按量计费，但数据出域且版本不可控；按敏感度分层，统一网关做路由、限流和降级）

## 场景题

1. 如果让你设计一个短链接系统，你会怎么设计？（发号器（号段 / 雪花）+ 62 进制编码，6 位约 568 亿；避免哈希截断冲突；可对 ID 混淆防遍历；MySQL 存映射 + Redis / 本地缓存扛读，布隆过滤器防穿透；用 302 而非 301，保证能统计点击；统计走 MQ 异步；过期策略、恶意链接检测、生成接口限流）
2. 订单下单后 30 分钟未支付要自动取消，你会怎么实现？各种方案怎么选？（定时扫表：简单但有延迟、压库，需索引 + 分批；MQ 延迟消息（RocketMQ 定时消息 / RabbitMQ TTL + 死信）：推荐主方案；Redis ZSet 轮询、时间轮：注意并发与持久化问题；主方案 + 定时扫表兜底；取消幂等 + 状态条件更新防与支付并发；回补库存、券也要幂等）
3. 设计一个类似微博或朋友圈的 Feed 流系统，推模式和拉模式怎么选？（拉模式（读扩散）：写便宜，读时合并关注人的发件箱，读延迟高；推模式（写扩散）：读快，大 V 写放大严重；推拉结合：普通用户推、大 V 拉；只推活跃粉丝；收件箱 / 发件箱用 Redis 存 ID 并限长，内容单独存储批量取；推送走 MQ 异步；分页用游标而非 offset）
4. 扫码登录是怎么实现的？（前提：手机 App 已登录；生成二维码 ID 存 Redis（待扫描，短 TTL），PC 轮询 / 长轮询 / WebSocket；手机扫码带 Token → 已扫描待确认，返回一次性临时凭证；手机确认 → 已确认，为 PC 签发新的独立 Token；安全：ID 随机一次性短时有效、确认页展示设备地点防钓鱼、状态流转校验）
5. 如何保证接口幂等，防止用户重复提交或者网络重试导致重复下单？（来源：用户连点、超时重试、网关重试、MQ 重复投递；前端置灰只是体验优化；Token 机制：Redis 原子删除成功才处理；业务唯一键 + 唯一索引；状态机条件更新（影响行数判重）；分布式锁只防并发；重复请求返回首次结果；封装注解 + AOP 组件）
6. 支付系统怎么防止重复支付？和第三方支付的对账怎么做？（一单一笔进行中支付单 + 状态条件控制 / 分布式锁；唯一商户订单号让第三方幂等；回调验签 + 状态条件更新幂等；下游通过 MQ 且各自幂等；定时主动查询兜底；识别跨渠道重复支付自动退款；每日对账：长款、短款、金额状态不一致 → 差错单，自动处理或转人工）
7. 设计一个高并发的优惠券领取系统，怎么防止超发和一人多领？（库存预热 Redis；Lua 原子完成判重 + 判库存 + 扣减 + 记录；MQ 异步落库削峰；数据库兜底：用户 + 券模板唯一索引；where stock > 0 条件更新；Redis 与 DB 不一致：事务消息 / 本地日志补偿 + 定时对账；热点库存拆分子 key；入口限流防刷；核销状态条件更新防重复使用）
8. 热点商品库存扣减，数据库单行更新成为瓶颈怎么办？（瓶颈：单行行锁串行，连接池被占满；扣减前移 Redis（Lua）+ 异步批量合并写库；库存拆分多行 / 多 key 提升并发，配合再平衡；条件更新 where num >= 1；热点行排队优化；请求合并、排队限流；定期对账与超时回补）
9. 设计一个即时通讯（IM）系统，消息的可靠投递、顺序和已读未读怎么保证？（接入层 Netty 长连接网关 + Redis 路由表；逻辑层负责存储与路由；可靠投递：客户端消息 ID，发送端与接收端双 ACK + 重试 + 去重；离线消息存储，上线主动拉取：推 + 拉结合；顺序：每会话单调递增序列号，客户端按序展示，发现空洞主动拉取；已读：记录已读到的最大序列号；大群读扩散）
10. 设计一个高并发的点赞系统，点赞数怎么计数？怎么防止重复点赞？（关系（谁赞了什么）与计数分开存储；Redis Set 记录关系，Lua 原子：SADD 成功才 INCR，SREM 成功才 DECR；MQ 异步落库，唯一索引兜底；计数定时批量回刷，避免热点行；超热内容：本地聚合后 INCRBY 或拆分子 key；批量判断已赞用 Pipeline / SMISMEMBER；冷数据从 Redis 淘汰）
11. 下单涉及订单、库存、优惠券、积分多个服务，怎么保证数据一致？（区分强一致（订单、库存、券）与最终一致（积分、通知）；低并发：Seata AT 全局事务，侵入小；高并发：TCC / 预扣 + 确认 + 超时释放，与订单超时取消流程结合；可靠消息 + Saga：本地消息表或事务消息驱动，失败发补偿；原则：全链路幂等、每步有补偿、定期对账巡检）
12. 线上某个接口突然变慢了，你的排查思路是怎样的？（确定影响面：单接口 / 全部、单实例 / 全部、开始时间点与变更关联；看大盘：QPS、P99、CPU、GC、线程池、连接池；看链路：慢请求耗时落在哪一段（DB、Redis、下游、内部）；DB：慢日志、执行计划变化、锁等待；内部：Arthas trace、jstack；先止血（回滚 / 扩容 / 降级 / 限流）再根治，复盘补告警）
13. Redis 出现大 Key 和热 Key 问题，怎么发现和处理？（大 Key 危害：阻塞单线程、带宽、删除阻塞、集群倾斜；发现：--bigkeys、MEMORY USAGE、离线分析 RDB；处理大 Key：拆分、精简压缩、UNLINK 或分批删除、限制集合增长；热 Key：集中访问打满单分片；发现：--hotkeys（需 LFU）、客户端统计、hotkey 框架；处理热 Key：本地缓存（最有效）、多副本 key 分散、读写分离、限流）
14. 双十一或大促之前，你会做哪些准备？容量评估和预案怎么做？（流量预估：历史数据 + 业务目标，按峰值并留余量；梳理核心链路与强弱依赖；单机压测 + 全链路压测找瓶颈，修复后复压；提前扩容应用与中间件，与第三方确认容量；预案：限流阈值、降级开关、熔断、缓存预热、应急手册；封网；值班盯盘；复盘）
